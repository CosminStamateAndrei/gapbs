Table~\ref{tab:systems} summarises the two systems. Both builds use \texttt{-g
-fno-omit-frame-pointer} so that call graphs can be sampled; this does not change the
generated loop code.

\paragraph{Laptop under WSL2.} WSL2 runs Linux in a Hyper-V virtual machine. This has three
consequences, which we state here because they bound what the laptop results can show.
(i)~The hardware performance-monitoring unit is not passed through: all hardware events
(cycles, instructions, cache and TLB misses) report \emph{not supported}. Only software
events and timer-based sampling are available. (ii)~The VM exposes 10 virtual CPUs without
hybrid topology, so P- and E-cores cannot be told apart or selected. (iii)~Guest memory is
translated twice (nested paging), which partly explains the high DRAM latency of
\SI{376}{ns} and adds variance. The laptop's sustainable bandwidth of \SI{15.9}{GB/s} is
low for this CPU; we use it as measured. We planned to boot a native Linux on the laptop
for hardware counters, but this was not possible in our time frame, so counters come from
Hábrók.

\paragraph{Hábrók.} The cluster provides neither \texttt{perf}, \texttt{numactl} nor a PAPI
module, and \texttt{perf\_event\_paranoid} is 2 (user-space counting only). We therefore built
PAPI~7.1 from source in our home directory. We also wrote \texttt{pecount}
(\texttt{pe/bench/pecount.c}, 200 lines), which counts a command's events through
\texttt{perf\_event\_open} like \texttt{perf stat}. All Hábrók runs used one exclusive node
through Slurm.
